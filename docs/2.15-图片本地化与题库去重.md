# 上岸通 2.15 · 图片全量本地化与题库去重

> 日期：2026-10-02 · 范围：把题库依赖的外部图片全部收回本地；修掉原去重逻辑的漏洞

## 1. 起因

排查「141 张缺失图片」时发现了一件更严重的事：

> 题库里有 **12,607 处图片引用指向粉笔的 CDN**（`fb.fbstatic.cn` / `fb.fenbike.cn`），
> 涉及 **8,631 道题**（占全库 15%）。这些图打开时才从粉笔服务器拉。

后果：断网看不到图；粉笔清理图片或加防盗链就全裂；用户打开这些题会把 IP 暴露给粉笔。

## 2. 两类外部图片

| 类型 | 地址形态 | 数量 |
|---|---|---|
| 题目配图 | `…/api/tarzan/images/162e6c35bfc7c65.png` | 5,285 个（去重） |
| 数学公式 | `…/api/planet/accessories/formulas?fontSize=18&latex=XXX`（无扩展名，返回 PNG） | 4,870 个（去重） |

**第一轮只处理了第一类**——正则要求地址以 `.png/.jpg` 结尾，公式地址没有扩展名，被漏掉了
14,340 处。是复查时从一道重复题的 `images` 字段里发现的。
随后又补了带查询串的 `.jfif?width=700`（5 处）。

**教训**：自查用的正则和改写用的正则一样，就会自己骗自己。复查必须换一种方式数。

## 3. 本地化结果

```
assets/img:  5,611 个文件 / 35.9 MB  →  10,896 个文件 / 198.5 MB
题库里的外部图片引用:  12,607 处 + 14,345 处  →  0 处
```

剩下的 13 处外部地址是正常的文本链接（GitHub、百度百科、新闻站、AI 接口示例），不是图片。

**比预估的 346 MB 少一半**：6,192 个地址里有一批在两个域名下重名，实际不同文件只有 5,285 个。

## 4. 顺带暴露的 814 道重复题

本地化之后，`test_v21_quality.py` 的「精确重复题=0」**失败了，报 814 组**。

根因：题库的去重键是「题干（含图片地址）+ 选项集」，而图片地址里带着 CDN 域名。
同一张图在 `fb.fbstatic.cn` 与 `fb.fenbike.cn` 下算两个不同地址，
于是同一道题被当成两道题留了下来。**域名差异一直掩盖着这批重复。**

核实过再动手：

| 检查项 | 结果 |
|---|---|
| 重复组数 | 814 |
| **答案一致的组** | **814 / 814** |
| 解析（前 200 字）一致 | 771 / 814 |
| 跨文件重复组 | 236 |
| 合并来源时的 (名称,题号) 冲突 | **0** |
| 被删题缺有效 src | **0** |

答案 814/814 一致 → 确实是同一道题（各省选调/模考常互相复用题目）。

### 处理：合并来源而不是简单删除

`scripts/dedupe_bank.py` 保留文件顺序里的第一份，把其余份的来源按「名称+题号」去重后
并入第一份的 `srcs`，再删掉其余份——这正是题库原本「多来源聚合」的设计。

```
待删 814 题，并入来源 2,284 条，改写 43 个文件
```

## 5b. 删掉 152 道缺图题

本地化之后仍有 141 张图片文件不在盘上（392 处引用，152 道题）。它们全在
`questions5.js` 的 2008–2011 年国考题里，题目对象只存本地哈希路径、**没有任何原始地址**，
补不回来。也查过「有带图双胞胎」——找到 26 道文字相同但**图片文件名不同**的，
那是同一段文字配了不同的图，属于不同题，不能顶替。

**决定删除，理由不是占地方，而是污染学习数据**：一道
「关于图中示意的自然现象，下列说法错误的是」没有图，只能瞎猜，
必然进错题本、进能力画像、进失分结构——把配速诊断和错因分析带偏。

```
152 道（0.26%）：资料分析 73、常识判断 37、判断推理 32、数量关系 10
其中 117 道所有图片都缺（完全无法作答），35 道只缺一部分
```

`scripts/prune_broken_images.py` 负责删除，`--dry-run` 只报数。

## 5c. 一个自己骗自己的 bug（两处，同一个毛病）

第一轮改写用的正则只匹配到扩展名为止，于是
`https://…/1671ccd3c3adbe1.png?width=700` 被改成
`assets/img/1671ccd3c3adbe1.png?width=700`——**查询串留在了路径里**。
文件其实在盘上（静态服务器会忽略查询串，所以页面看着正常），但路径是脏的。

更麻烦的是：第一轮的「残留 0 处」自查，用的是**和改写同一个正则**，
所以查不出来；后来统计「缺图题」时用 `os.path.basename()` 一比，
**误报成 7,969 道题缺图**（真实是 152 道）。

两处都是同一个毛病：**自查和改写用同一套判断逻辑，等于没查。**
现在 `localize_images.py` 里加了 `DIRTY_RX` 专门清这类残留（一次清掉 11,676 处），
统计脚本也改成独立地按文件名对盘。

## 6. 工具

| 脚本 | 作用 |
|---|---|
| `scripts/localize_images.py` | 下载 + 改写两类外部图片、清历史脏路径、重算 manifest 指纹。幂等可续传；`--check` 只检查 |
| `scripts/dedupe_bank.py` | 精确去重并合并多来源；`--dry-run` 只报数 |
| `scripts/prune_broken_images.py` | 删除引用了缺失图片的题；`--dry-run` 只报数 |

manifest 的 `build` 指纹按 `rebuild_bank.py` 同样的算法重算（所有分片字节的 sha256 前 16 位），
否则老用户的浏览器缓存不会失效、看不到新图。
