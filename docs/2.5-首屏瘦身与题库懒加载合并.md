# 上岸通 2.5 · 首屏瘦身与题库懒加载合并

> 日期：2026-10-02 · 范围：首屏同步 JS 瘦身、真题库并入懒加载体系、回归基线更新

## 1. 原问题

`index.html` 同步加载 `questions5.js` + `questions7.js` + `questions8.js`（共 28.94MB / 13,073 题），
浏览器必须下载并解析完这 28.94MB 才能渲染首页。该问题在
`docs/2.1-问题诊断报告.md` 中列为 P0，v2.2 只把 `questions6.js` 挪进了懒加载，三份真题库一直留在首屏。

实测（Playwright + 系统 Chrome，本机 `127.0.0.1:8140`）：

| 指标 | 改造前 | 改造后 |
|---|---:|---:|
| 首屏同步 JS（解码体积） | 28.94 MB / 8 个请求 | 0.93 MB / 7 个请求 |
| DOMContentLoaded（本机） | 191 ms | 45 ms |
| 首页可见（本机） | 247 ms | 151 ms |
| **DOMContentLoaded（限速 10Mbps / 40ms RTT）** | **23,690 ms** | **992 ms** |
| **首页可见（限速 10Mbps / 40ms RTT）** | **23,708 ms** | **997 ms** |

本机 localhost 带宽约 87MB/s，所以改造前的 4~6 秒级白屏在本机看不出来；
一旦部署到公网服务器给他人使用，28.94MB 首屏就是 20 秒以上的白屏。

## 2. 实现方案

改动刻意复用已有的懒加载机制，没有新增加载路径：

1. **新增** `js/bank/questions-zhenti-manifest.json`：3 个分片、13,073 题，
   不写 `build` 字段，签名由 `file:bytes:count` 自动指纹化，文件内容变化即自动失效缓存。
2. **修改** `js/lazy-bank.js` 的 `fetchManifests()`：由两份 manifest 改为三份，
   `chunks` 顺序为 `真题 → questions6 → questions9`；签名增加 `zt:` 段。
   - 真题三份是 7~14MB 的大文件，排在队首可与后续小分片共用 6 路并发窗口，
     避免尾批单飞一个 14MB 文件。
3. **修改** `index.html`：移除三个同步 `<script>`，首屏只保留基础题库
   `questions.js ~ questions4.js`（882 题 / 约 0.84MB）。

首屏不依赖这三份文件：仪表盘只读 `localStorage` 与 `MODS`（模块键名，基础题库中六个键均已存在），
题库题量与检索均在 `requireFullBank()` 之后渲染。

## 3. 题库构成（新基线）

| 来源 | 题量 | 加载方式 |
|---|---:|---|
| `questions.js ~ questions4.js` | 882 | 首屏同步 |
| `questions5/7/8.js`（国考/省考/选调真题） | 13,073 | 懒加载（本次并入） |
| `questions6_*.js`（模考库，39 分片） | 43,103 | 懒加载 |
| `questions9_*.js`（省考模考大赛，13 分片） | 2,010 | 懒加载 |

## 4. 缓存失效

签名由 `q6:...|q9:...|zt:...` 三段组成。本次改动使签名变化，**老用户的旧 IndexedDB 缓存会
自动失效并重新下载一次完整题库（约 164MB）**，这是保证不出现"少 13,073 题"的必要代价。

`js/lazy-bank.js` 的 `?v=` 查询串必须随该文件改动递增。若沿用旧 `?v=`，
老用户浏览器里缓存的旧 `lazy-bank.js` 不认识新 manifest，会静默只加载 45,113 题。

## 5. 部署注意（公网服务器）

1. **必须开启 gzip / brotli**。题库 JS 合计 163.6MB，压缩后约 35~40MB。
   nginx：`gzip on; gzip_types application/javascript application/json;`
2. **`index.html` 不要长缓存**（`Cache-Control: no-cache` 或短 TTL），
   否则用户拿不到新版本引用，`?v=` 机制失效。
3. **带 `?v=` 的静态 JS / CSS 可长缓存**（`immutable, max-age=31536000`）。
4. 题库分片与图片可用 CDN 或加长缓存，文件名即内容指纹。

## 7. 本次未处理的既有问题

1. **141 张题目图片缺失**：题库引用的 1,142 张图片中有 141 张不在 `assets/img/`，
   页面加载时 404（全部来自 `questions5.js` 国考真题）。`test_v01.py` 的「无JS错误」项因此失败。
   该缺陷在本次改动前就存在，只是 `test_v01.py` 因 Windows GBK 解码崩溃（已修）从未跑到浏览器阶段。
2. **4,610 张图片在盘但无引用**，合计 15.4MB，部署时会白扛流量。
3. **申论素材库仅 21 条硬编码**（`js/shenlun.js`），与 59,068 题的题库量级严重不匹配。
4. **问泽 AI 只有 UI 壳**：`sendAsk()` 只改状态文案，不发请求；接入需要
   `docs/ai_proxy_contract.yaml` 所述代理层。
5. **无 service worker**：README 所称「离线可用」目前仅指题库走 IndexedDB 缓存，
   应用外壳本身在断网后无法打开。
