# 上岸通 2.17 · AI 输出的 Markdown 渲染

> 日期：2026-10-02 · 范围：AI 回答按 Markdown 渲染，不再是字面量

## 1. 问题

AI 回答的都是 Markdown（`## 标题`、`1. 列表`、`**加粗**`），而前端是用 `esc()` 原样显示的，
于是页面上看到的是字面量的星号和井号。

## 2. 实现：手写极简渲染器，不引依赖

项目是**零依赖纯前端**（没有 `package.json`、没有构建步骤）。为了渲染 Markdown 引入
marked 之类的库，等于给一个零依赖项目开个口子，只为几种语法。

`js/app.js` 新增 `mdToHtml()`，约 25 行，只覆盖 AI 实际会用的语法：

| 语法 | 输出 |
|---|---|
| `## 标题`（1–4 级） | `<div class="md-h md-hN">` |
| `- 项目` | `<ul class="md-ul">` |
| `1. 项目` | `<ol class="md-ol">` |
| `> 引用` | `<div class="md-quote">` |
| `**粗**` / `*斜*` / `` `码` `` | `<b>` / `<i>` / `<code>` |
| 空行 | `<div class="md-gap">` 段间距 |

**表格不支持**——AI 在当前的 prompt 约束下很少用，真要渲染表格代码量会翻几倍，YAGNI。

## 3. 安全：先转义再替换

渲染 Markdown 天然是个注入点。做法是**先把整段文本 `esc()`，再在转义后的文本上做替换**，
所以 AI 输出里的 `<script>`、`<img onerror=...>`、`javascript:` 链接都只会显示成文字。

测试专门覆盖这一条（见 §5）。

## 4. 一处踩到的坑

`esc()` 会把 `>` 转成 `&gt;`，所以引用检测的正则 `^\s*>` **永远匹配不到**。
改成匹配转义后的 `^\s*&gt;\s?` 才对。这个 bug 是测试抓出来的。

## 5. 应用位置

| 位置 | 说明 |
|---|---|
| AI 学情诊断 / AI 排计划 | `aiCardHtml()` 的结果区 |
| 问泽回答 | `.ask-answer-body`（同时去掉了它的 `white-space:pre-wrap`，排版交给渲染器） |
| 申论批改反馈 | 练笔记录展开后的正文 |

AI 猜错因那条是 toast，不需要渲染。

## 6. 验收

```
SAT_TEST_URL=http://127.0.0.1:8140/index.html python scripts/test_v217_md.py
==== v2.16 Markdown 渲染验收：通过 18/18，失败 无 ====
```

覆盖两类：

**安全**（4 项）：`<script>` 被转义、加粗里的 `<img onerror>` 被转义、
列表里的 `javascript:` 链接被转义、裸 `&` 与 `<` 被转义；
再把结果真的插进 DOM，断言**没有产生 img/script 节点、没有代码被执行**。

**语法**（8 项）：二级标题、加粗、斜体、有序列表、无序列表、引用、行内码、
空行段间距、列表标签正确闭合。

**真接到 AI 上**（2 项）：拦截接口返回 Markdown，断言页面上出现真实的
`<b>`、`<ol><li>`、`.md-h2` 节点，且**看不到字面量的 `**` 和 `##`**。

全套 20 个测试通过。

## 7. 本次未做

1. **表格渲染**——需要按行解析 `|` 并生成 `<table>`，代码量与收益不成比例。
2. **代码块（三反引号）**——AI 讲题时基本不输出代码块，暂不做。
3. **流式渲染**——目前是等完整回答返回后一次性渲染。
