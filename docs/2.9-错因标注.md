# 上岸通 2.9 · 错因标注

> 日期：2026-10-02 · 范围：给错题标注错因，生成「失分结构」，把三个不同的病分开治

## 1. 要解决的问题

用户反馈：「正确率上不去」。

但**「错」不是一个病，是三个病**：

| 错因 | 本质 | 对策 |
|---|---|---|
| **不会** | 知识点缺口 | 补知识点（错题本、薄弱考点清单） |
| **来不及** | 取舍策略问题 | 练取舍（配速诊断已能定位时间黑洞） |
| **粗心** | 审题习惯问题 | 放慢读题、圈关键词、逐个排除——**刷更多题不会改善** |
| **蒙的** | 基础不牢 | 回到简单档打底子，别急着做难题 |

改造前 App 只记录对错，这四种混在一起。用户看到 40% 正确率，不知道该补知识点、
该练取舍、还是该练审题——**而这三件事的解法南辕北辙**。

## 2. 实现

### 2.1 数据层

`store.attempts[]` 新增 `why` 字段，取值 `'' | '不会' | '来不及' | '粗心' | '蒙的'`。

- `logAttempt()` 创建记录时写入 `why:''`；
- `normalizeStore()` 用白名单过滤：非法值置空、缺字段补空，
  **旧备份（完全没有 why 字段）可正常导入**。

### 2.2 标注入口

放在**逐题回顾页**——用户本来就在逐题看解析，顺手标注摩擦最小。

- 只在 `Q.mode==='review'` 且该题**答错或未作答**时出现；
- 四个按钮，再点一次即取消，也可直接改标成别的错因；
- 交卷结果页给一句提示，引导她去回顾里标注。

### 2.3 失分结构

能力分析页新增「🧭 失分结构（错因分布）」卡：

- 标注数 **< 5 条不显示**（样本不足不下结论，与配速诊断一致）；
- 展示各错因的题数与占比；
- 按**占比最高**的那个错因给出对应建议，例如「来不及」占多数时提示
  「这是取舍问题，不是能力问题。看上面的配速诊断，把时间黑洞模块放到最后并限时」。

未新增数据文件，也未改动题库与缓存逻辑。

## 3. 新增代码

`js/app.js`：

| 新增 | 作用 |
|---|---|
| `WHY_OPTIONS` / `WHY_COLOR` | 错因白名单与配色（定义在 `load()` 之前，供 `normalizeStore` 使用） |
| `whyOf(qid)` | 取该题最近一次作答的错因 |
| `markWhy(qid, why)` | 写入/取消标注并重绘回顾页 |
| `whyStats()` | 汇总错因分布，样本不足返回 `null` |
| `whyCardHtml()` | 渲染失分结构卡 |
| `wrongReasonHtml(q, chosen)` | 回顾页里的标注按钮组 |

`css/style.css` 新增 4 条规则（`.why-box` / `.why-row` / `.why-chip` / `.why-chip.on`），
既有样式无法直接复用（`.ask-chip` 没有选中态、`.chip.active` 是 `.sl-nav` 作用域内）。

## 5. 与配速诊断的分工

两个功能是配套的：

- **配速诊断**回答「时间花在哪、该放弃什么」——解决「来不及」；
- **错因标注**回答「我到底是不会还是来不及」——决定该用哪个工具。

先看失分结构确定病因，再对症下药，而不是一律「多刷题」。
