# 上岸通 2.10 · AI 接入与学情诊断

> 日期：2026-10-02 · 范围：从零建 AI 接入层；AI 第一个落点是「读学情数据出诊断」

## 1. 改造前：问泽是个空壳

`js/app.js` 的 `sendAsk()` 只改状态文案，**不发任何请求**。UI、按钮、语音输入都在，
后端能力为零。`docs/3.0-公考AI-Agent设计方案.md`（326 行）与
`docs/ai_proxy_contract.yaml`（4 个接口）是完整方案，但一行未实现。

## 2. 关键发现：不需要写后端

原方案假定必须有个 Python 服务做代理。实测 `api.deepseek.com` 的 CORS 预检：

```
OPTIONS /v1/chat/completions   Origin: http://127.0.0.1:8140
→ 200
  Access-Control-Allow-Origin:  http://127.0.0.1:8140
  Access-Control-Allow-Methods: POST
  Access-Control-Allow-Headers: authorization,content-type
```

**接口允许浏览器直连**。因此 App 保持纯前端：用户在前端填接口地址、模型名、Key，
浏览器直接调用，甲骨文服务器依旧只发静态文件。

若某个第三方端点不允许浏览器直连，把「接口地址」填成自己的代理地址即可——
接入层不区分「直连」与「代理」，都是同一个 URL 字段。

## 3. 三条设计约束

### 3.1 Key 与学习数据分开存

Key 存在独立的 `zhize_ai_cfg_v1`，**不进 `shangan_tong_v1`**。
否则「导出备份」会把 API Key 一起导出并交给别人。

### 3.2 只发统计数据，不发题目和答案

`studySnapshot()` 的字段是固定的统计量：
考试目标、剩余天数、每日目标、连续天数、累计作答、总正确率、各模块正确率与题量、
平均每题用时、配速四象限、错因分布、薄弱考点名。

**不含题干、选项、解析、答案。** 原因有二：隐私，以及——AI 判断答案不可靠
（本次开发中实测到 AI 生成的考公内容三次出错：十五五规划发布方式、十五五与十四五关系、
申发论述题型定义）。AI 负责解读数据、给建议；**不负责判断答案**。

system prompt 里也写死了这条：`不要给出任何题目的答案，也不要猜题`。

### 3.3 「已配置」必须含 Key

默认值预填了 DeepSeek 的地址与模型，若 `ready()` 只看这两项会**误判成已就绪**，
用户点下去只会拿到一个 401。因此 `ready() = url && model && key`。
（不需要 Key 的本地代理，填任意占位串即可。）

## 4. 接入层 `js/ai.js`

| 导出 | 作用 |
|---|---|
| `AI.loadCfg()` / `AI.saveCfg()` | 读写配置（地址 / 模型 / Key），存独立 localStorage |
| `AI.ready()` | 是否已可用（地址 + 模型 + Key 都非空） |
| `AI.chat(messages, opts)` | OpenAI 兼容调用，`AbortController` 超时，默认 90 秒 |
| `AI.listModels()` | `GET /models` 拉取可用模型列表（去重排序） |
| `AI.modelsUrl(chatUrl)` | 由对话地址推出模型列表地址 |
| `AI.describeHttpError()` | 把 HTTP 状态翻译成用户能照做的动作 |

**模型不用手输。** 配置页有「获取模型列表」按钮，点一下按下面的规则推导地址、
拉回列表、渲染成下拉框，选一个即写回模型字段并保存：

```
.../v1/chat/completions  →  .../v1/models
.../chat/completions     →  .../models
.../v1                   →  .../v1/models
```

手输仍然保留（个别中转站不实现 `/models`）。

错误文案按「用户下一步该做什么」写，而不是甩状态码：

| 状态 | 文案 |
|---|---|
| 401 / 403 | AI 鉴权失败：请检查 API Key 是否填对、是否已过期 |
| 404 | AI 接口地址不对（404）：请检查地址是否以 `/v1/chat/completions` 结尾 |
| 429 | AI 提示请求过于频繁或额度不足（429），稍后再试 |
| 5xx | AI 服务端错误（NNN），稍后重试 |
| 网络 / CORS | 连不上 AI 接口：可能是网络不通，或该接口不允许浏览器直连（CORS） |
| 超时 | AI 请求超时，请重试 |

## 5. 第一个落点：AI 学情诊断

位置：「修业成长 → 能力图谱」页顶部。只发送统计快照，返回后渲染在卡片里，
标注 **AI 生成 · 仅供参考**。

system prompt 约束输出结构（`【最关键的 2 个问题】/【接下来两周怎么做】/【一句提醒】`，
350 字以内），并禁止编造与泄答案。

数据少于 20 题时拒绝调用——样本不足时 AI 只会编。

## 6. 验收

```
SAT_TEST_URL=http://127.0.0.1:8140/index.html python scripts/test_v210_ai.py
==== v2.10 AI 接入验收：通过 43/43，失败 无 ====
```

不需要真实 API Key：用 Playwright 拦截 `/chat/completions` 与 `/models`，验证请求格式与渲染。覆盖：

- AI 接入层加载、配置页三个输入框、Key 用密码框；
- 未配置时给出「去配置」引导；
- **Key 不进 `store`、不进导出备份**，与学习数据分属两个存储键；
- 快照字段固定，prompt 含模块/配速/错因/目标，**不含题干、options、answer、analysis**；
- 请求 URL、`Authorization: Bearer`、模型名、system+user 两条、`stream:false` 全部正确；
- system 里确实写入了「不要编造」「不要给出任何题目的答案」；
- 401 / 404 / 429 / 500 / 连不上 五类错误的文案都可照做；
- 数据少于 20 题时不发起请求；
- **模型列表**：地址推导正确、带鉴权头、选项去重排序、选中后写回并保存、失败时提示可照做且按钮恢复可用。

## 7. AI 还能插进哪里（下一步）

用户的要求是「让 AI 参与分析和制定」，不限于问泽。按价值与风险排序：

| 落点 | AI 做什么 | 依赖 | 风险 |
|---|---|---|---|
| **AI 制定学习计划** | 依据学情快照生成具体到每天的复习安排 | 无（复用 `studySnapshot`） | 低 |
| **AI 讲解错题** | 对着**题库原始解析**换说法讲透、追问 | 需把题目喂给 AI | 中（须以题库解析为准，禁止 AI 自行判断答案） |
| **AI 预填错因** | 看题目、她的选项、用时，猜错因供她确认 | 同上 | 低（她可改） |
| **AI 学情周报** | 每周汇总进度与变化趋势 | 无 | 低 |
| **申论批改** | 分项反馈 + 引用原文为证 | 需先有申论题库 | 高（主观、易误导） |
