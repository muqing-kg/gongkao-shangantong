# 上岸通 2.6 · 学习计划

> 日期：2026-10-02 · 范围：目标考试与每日题量、倒计时、今日进度、本周达标、今日计划组题

## 1. 设计取舍：只存目标，不存任务

**存**三个字段：目标考试、考试日期、每日题量。
**不存**每日任务清单与完成状态——"今天做了多少题"这个事实 `store.checkins` 里本来就有。

理由：任务一旦落库，隔几天不打开就会积压一堆过期任务，还要额外处理跨天滚动、补签、时区；
而由 `checkins` 推导出来的进度永远和真实作答一致，不会出现"计划说完成了 30 题、统计说 12 题"。

代价：当前版本**不能预先安排未来某天的任务**（例如"下周三做资料分析"）。
真需要时再加 `plan.tasks` 数组，不必现在预留。

## 2. 数据模型

```js
store.plan = { exam: '2026 国考', date: '2026-11-29', daily: 80 }
```

`normalizeStore()` 的规范化规则（导入备份走同一条路径）：

| 字段 | 规则 |
|---|---|
| `exam` | 纯文本，截断到 30 字 |
| `date` | 必须匹配 `YYYY-MM-DD`，否则置空 |
| `daily` | 非法值（负数/非数字）→ 默认 60；1~9 → 夹到 10；>200 → 夹到 200 |

计划随「导出备份 / 导入恢复」一起走，因为 `exportData()` 序列化整个 `store`。

## 3. 派生逻辑（全部无状态）

| 函数 | 含义 |
|---|---|
| `planTarget()` | 每日目标题量，夹在 10~200 |
| `planDone()` | 今日已完成 = `checkins[today].answered` |
| `planDaysLeft()` | 距考试天数；未设日期返回 `null`，已过为负数 |
| `planHitDays(n)` | 最近 n 天里达标（作答 ≥ 目标）的天数 |
| `weakMods(k)` | 作答 ≥5 次且正确率最低的 k 个模块，由 `smartQuiz()` 与本页共用 |

## 4. 入口与交互

「修业成长」页首张卡片 →「学习计划」。日期用原生 `<input type="date">`，
表单复用既有 `.field` 样式，未新增任何 CSS。

「开始今日计划」的组题顺序：**到期错题 → 薄弱模块补齐 → 全库随机**，
题量 = 每日目标 − 今日已完成（已完成超额时按钮变为「继续加练」）。
