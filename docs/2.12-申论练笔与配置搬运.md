# 上岸通 2.12 · 申论练笔与配置搬运

> 日期：2026-10-02 · 范围：补上申论（占笔试一半、此前零练习）与降低 AI 配置门槛

## 1. 为什么申论这块绕不过去

省考笔试 = 行测 + 申论，各占一半。此前 App 的行测有 59,068 题，
申论却**只有素材、没有任何练习**——她能练的只有笔试的一半。

但申论题库拿不到可靠来源（早先指向的那个 GitHub 仓库连账号都注销了，
实测 404），而且申论没有标准答案，靠 AI 生成题目只会教错。

**解法：不依赖题库。** 考生自己贴题目要求与作文，AI 按测评维度给反馈。
题目从她的真题卷里来，不需要 App 提供。

## 2. 两条硬约束

申论批改是本次 AI 落点里**风险最高**的一个——AI 极容易给出看着专业、
实际误导的评价。因此在 system prompt 里写死两条：

| 约束 | 原文 |
|---|---|
| **绝不给分数** | 「你给的是**参考反馈，不是分数**。绝对不要给出『你能考 XX 分』这类判断，也不要预测分数区间或档次——分数只能由阅卷人给出。」 |
| **必须引用为证** | 「每段**必须先引用考生原文里的一句话**作为依据，再指出问题或优点」「不要只说『建议加强』」 |

另外固定输出结构：先判断跑题与否（没给题目要求就直说无法判断），
再按【立意与观点】【结构与层次】【论证与素材】【语言与表达】四段，
最后【最该改的一处】——只挑一处，说清怎么改。

## 3. 数据与交互

- `store.essays = [{id, at, requirement, body, feedback}]`，上限 `ESSAY_LIMIT = 30` 篇，
  超出丢弃最旧的；随「导出备份」一起走（属于学习数据）。
- `normalizeStore()` 白名单校验：无 `id` 或无 `body` 的记录丢弃；
  `requirement` 截断 2000 字、`body`/`feedback` 各截断 6000 字。
- 作文少于 200 字直接拒绝提交，不浪费一次请求。
- 记录默认收起（`essayOpen` 是内存态，刷新后回到收起），可展开、可删除。

## 4. 配置搬运：降低 AI 配置门槛

原先要她自己在手机上敲接口地址、模型名和一长串 Key，对不懂技术的人是个坎。

现在配置卡多了两个按钮：

| 按钮 | 行为 |
|---|---|
| **复制我的配置** | 把 `{url, model, key}` 编成一段 `ZSAI1:…` 文本放进剪贴板；剪贴板不可用（非 HTTPS）时自动填入输入框让人手动复制 |
| **导入配置** | 粘贴这段文本即完成配置，无需手敲 |

格式：`ZSAI1:` + base64(JSON)。前缀用于识别内容是否对得上；
base64 只是让文本便于整段复制粘贴，**不是加密**——对方拿到就能用，属于预期行为。

错误处理区分三种情况：空内容、base64/JSON 解不开（提示确认整段复制完整）、
解出来没有 `url`（提示配置里没有接口地址）。

```
SAT_TEST_URL=http://127.0.0.1:8140/index.html python scripts/test_v210_ai.py
==== v2.10 AI 接入验收：通过 58/58，失败 无 ====   （含配置搬运 6 项）
```

`test_v212_essay.py` 覆盖：入口与计数、作文过短不请求、未配置时不请求、
system 里确实写了「不是分数」「绝对不要给出」「必须先引用考生原文里的一句话」、
四个维度与【最该改的一处】、user 带题目要求与正文、结果渲染与落库、
刷新后仍在、默认收起与展开、`normalizeStore` 过滤与 30 篇上限、删除。

`test_v210_ai.py` 新增部分覆盖：导出带前缀且不含明文 Key、换配置后导入完整还原、
非法内容与缺地址两种错误提示。
