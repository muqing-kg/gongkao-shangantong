## 一、结论先行：必须加一个后端

主人提的三件事里，**有三件纯前端做不到**：

| 需求 | 纯前端能行吗 | 为什么 |
|---|---|---|
| 密码登录 | ❌ | 前端 JS 是公开的，校验逻辑谁都能看、能绕过。必须服务端比对 |
| 后台看她的学习情况 | ❌ | 数据只存在她浏览器的 localStorage 里，主人的电脑上根本看不到 |
| 集中配置 API Key | ❌ | Key 一旦下发到浏览器，**任何打开页面的人按 F12 就能拿到**。必须服务端代理 |

所以项目要从「纯前端」变成「前端 + 一个小后端」。

**好消息**：题库（198 MB 图片 + 29 MB 题）本来就是静态资源，继续静态托管不动。
后端只干四件事——**登录、同步、AI 代理、后台**，很轻。

## 二、现状体检：哪些该砍

主人说「好多内容好像没必要存在了」。妾身逐条过了一遍，**该砍的比想象中多**：

### 2.1 建议删除

| 东西 | 为什么砍 |
|---|---|
| **番茄专注钟** | 刷题自带计时器，一个考公 App 里再放番茄钟是功能重叠，她不会用。一个功能存在但没人用，就是负债 |
| **「更多」这一整页** | 现在是个杂物抽屉：打卡日历、番茄钟、复习提醒、题库缓存、数据管理、关于全塞在一起。拆开各归其位，这一页就不需要了 |
| **备考小贴士** | 现在是写死的通用建议，价值低。**这一块位置正好腾给「主人写的话」**（见 §5.3） |
| **题库离线加速** | 不是功能，是一个开关。挪进设置里，不单独占地方 |
| **「问泽」作为主 tab** | 它现在既是 tab，又到处有入口（顶栏、首页、题目下方）。**降级为全局入口**，把 tab 位让给更常用的「错题本」 |

### 2.2 建议合并

| 现状 | 合并为 |
|---|---|
| 行测研习 + 每日研习（两个独立入口） | 合成一个「行测」，每日一练作为其中一个按钮 |
| 修业成长（能力图谱 / 配速诊断 / 失分结构 / 学习计划） | 保留，但**重排为「一眼看懂」的顺序**，现在卡片太多太长 |
| 我的书斋 + 更多 | 合成一个「我」：数据管理、AI 状态、隐私、关于 |

### 2.3 建议保留（这些是核心价值）

- 行测刷题（练习 / 每日 / 组卷 / 导出打印）
- 错题温习（艾宾浩斯复习）
- 申论书房（真题 12 卷 + 素材 55 条 + 练笔批改）
- 修业成长（能力图谱、配速诊断、失分结构、学习计划）
- 问泽（逐题讲解 + 学情诊断）

### 2.4 重构后的导航（6 个 tab）

```
PC/平板（左侧栏）              手机（底部）
├─ 首页                        ├─ 首页
├─ 行测                        ├─ 行测
├─ 错题本  ← 新增（原在行测里）  ├─ 申论
├─ 申论                        ├─ 成长
├─ 成长                        └─ 我
└─ 我
                              问泽：全局悬浮按钮，不再占 tab
```

**理由**：她的真实动线是「打开 → 今天练什么 → 刷题 → 看错题 → 偶尔问 AI」。
错题本现在是藏在行测里的二级入口，但她备考后期**主要就是在刷错题**，值得提到一级。

## 三、目标架构

```
┌──────────────────────────────────────────────────┐
│  浏览器（她的手机 / 平板 / PC）                    │
│  响应式 SPA（重写）                                │
│  localStorage = 学习数据的本地副本（断网也能刷题）  │
└──────────────────┬───────────────────────────────┘
                   │ HTTPS
┌──────────────────▼───────────────────────────────┐
│  Node 服务（甲骨文服务器）                         │
│                                                   │
│  静态托管   /            → 前端文件（gzip+brotli）  │
│            /assets/     → 题库图片（强缓存）        │
│                                                   │
│  学习端 API                                        │
│    POST /api/login          密码 → 会话            │
│    GET  /api/progress       拉取学习数据            │
│    PUT  /api/progress       上传学习数据（增量）     │
│    POST /api/ai             AI 代理（Key 在服务端）  │
│    GET  /api/messages       他留的话                │
│                                                   │
│  管理端 API（需管理密码）                           │
│    GET  /api/admin/overview  她的学习概览           │
│    GET  /api/admin/trend     趋势数据               │
│    PUT  /api/admin/ai        AI 配置                │
│    PUT  /api/admin/message   写留言                 │
│    PUT  /api/admin/goal      设定考试日期与目标      │
│                                                   │
│  SQLite（单文件，零配置）                           │
│    users(角色, 密码哈希) · progress(数据快照)        │
│    messages(留言) · goals(目标) · config(AI 配置)   │
└───────────────────────────────────────────────────┘
```

### 关键技术取舍

| 项 | 选择 | 理由 |
|---|---|---|
| 后端语言 | **Node.js**（与前端同语言，服务器上装一个 Node 就够） | 不必再引入 Python 运行时 |
| 框架 | **Express**（或原生 http） | 只有 10 个接口，不需要 NestJS 那套 |
| 数据库 | **SQLite**（better-sqlite3） | 单用户系统，一个文件搞定，备份就是复制文件 |
| 前端构建 | **仍然零构建** | 现在的「改完直接生效、部署就是复制文件」是优点，重构风格不需要构建工具 |
| 样式 | 手写 CSS + 自定义属性 + 断点 | 6 个 tab 的规模，引 Tailwind 是杀鸡用牛刀 |

## 四、登录设计

### 4.1 形态

- **不注册**。主人（或妾身）在服务器上设一次密码，之后她输密码就进。
- 两个角色两个密码：
  - **她的密码** → 学习端
  - **管理密码** → `/admin` 后台

### 4.2 怎么设密码

一条命令，在服务器上跑：

```bash
node server/set-password.js --user her   --password "xxxx"
node server/set-password.js --user admin --password "yyyy"
```

密码用 scrypt 加盐哈希后存进 SQLite，**明文不落盘、不进代码、不进 Git**。

### 4.3 会话

- 登录成功 → 服务端签发 **httpOnly + SameSite=Lax 的签名 Cookie**，有效期 30 天
- 她一个月内不用重输密码；换设备要重输
- **登录失败限速**：同一 IP 5 次/分钟。单一密码的系统必须防爆破

### 4.4 一个要提醒主人的点

单个密码 = 单点。如果她忘了密码，主人用管理命令重置即可，不会锁死。
但**如果密码泄露，任何人都能看到她的全部学习数据**。建议密码别用生日这类。

## 五、后台设计

### 5.1 主人能看到什么

| 板块 | 内容 |
|---|---|
| **今日** | 做了多少题、正确率、用时、是否打卡 |
| **趋势** | 近 30 天每日题量与正确率曲线 |
| **模块** | 六个模块的正确率 / 平均用时 / 与上周对比 |
| **薄弱考点** | 正确率最低的考点 Top 10（这是最有价值的） |
| **错题** | 她的错题清单与错因分布 |
| **申论** | 练笔篇数、AI 批改记录 |
| **状态** | 最后活跃时间、连续打卡、距离考试还有几天 |

### 5.2 AI 配置（主人配，她不用管）

后台填：接口地址、Key、模型。存在服务端，**前端永远拿不到 Key**。
她在前端只看到「AI 已就绪」，不需要任何配置。若主人没配，前端提示「AI 暂不可用」，不暴露细节。

### 5.3 互动（主人问的「能不能跟她互动」）

妾身建议做**三件克制的**，不做聊天室那种花哨的：

| 功能 | 形态 |
|---|---|
| **留言** | 主人在后台写一段话 → 她的**首页**显示（就是现在「备考小贴士」那块位置）。她看不到「这是后台推的」，就是一句放在那儿的话 |
| **目标** | 主人设定考试日期与每日题量 → 她首页显示倒计时与今日进度 |
| **里程碑寄语** | 主人预先为「连续 7 天 / 30 天 / 做满 1000 题」写好话，达成时弹出 |

**为什么不做实时聊天**：她要的是安静备考，实时消息会变成打扰，也容易让她分心。
留言这种「异步、不催促」的形态更贴合。

### 5.4 后台的安全

- `/admin` 独立路径 + 独立密码
- 后台的所有接口都要管理会话
- 后台不进搜索引擎（`robots.txt` + 响应头）

## 六、风格与文案

主人说提供不了文案，让妾身来。这是方案里最主观的一块，妾身先给方向和样例，主人挑。

### 6.1 保留什么

现在的**国风淡墨**底子（宣纸米色 + 深蓝 + 金，淡墨背景）**建议保留**：
它本来就不晃眼，也贴合「读书」这件事。要改的是**排版、留白、层级**和**全部文案**。

### 6.2 基调：安静的陪伴感

一句话定调：**像一个懂她的人在旁边，不喊口号、不卖萌、不煽情。**

四条具体手法：

1. **克制的人称**——文案里可以有「我」（主人），但要少而准，不腻。
2. **不出现称呼**——页面上不写「老婆」这类词。她要给别人看手机时不尴尬，肉麻反而会让她不好意思用。
3. **说人话**——不用「赋能」「开启你的备考之旅」这类词。
4. **状态感知**——按时间、进度、连续天数变化，而不是永远一句「欢迎回来」。

### 6.3 文案样例（主人挑方向）

| 位置 | 现在 | 提案 A（陪伴） | 提案 B（克制） |
|---|---|---|---|
| 首页问候 | 今日研习 | 今天也一起 | 今天练点什么 |
| 连续打卡 | 连续学习 0 天 | 第 0 天，不急 | 已连续 0 天 |
| 没刷题时 | 还没有作答记录——先刷几题 | 还没开始呢，不着急 | 暂无记录 |
| 加载题库 | 正在加载完整题库… | 题库在准备了，稍等一下 | 正在加载题库 |
| 交卷后 | 本轮正确率 X% | 这一轮 X%，错的都记下了 | 正确率 X% |
| 错题本空 | 暂无错题 | 一道错题都没有，今天很稳 | 暂无错题 |
| 该备份了 | 该备份了 | 记录该存一份了 | 建议备份 |
| 关于页 | （技术说明） | 为你而做 | — |

**妾身推荐 A**，但把「今天也一起」这类稍微收一点——满屏都是「一起」也会腻。
真正的分寸是：**大部分地方正常说话，只在少数几个节点放一句有温度的话。**

### 6.4 AI 的人格（主人明确要求的）

现在 AI 的设定是「你是一位公考（省考）备考助手」——纯工具人。提案改为：

```
你是一位耐心的公考辅导老师，正在帮一位备考省考的考生。
这套系统是她的伴侣为她搭的——你的回答应当温和、笃定，
像一个认识她、希望她好的人在旁边陪着。

但要注意分寸：
- 温和不等于空泛鼓励。该指出的问题要直接指出，她要的是提分，不是安慰。
- 不卖萌、不堆感叹号、不说「加油哦」这类空洞的话。
- 鼓励和批评都要**具体到她的数据和题目**，不要泛泛而谈。
- 用中文，说人话。
```

**核心原则**：**鼓励要具体**。「你今天资料分析比上周快了 12 秒」比「你真棒」有用一百倍。

## 七、多端适配

现在已有断点（380 / 640 / 767 / 1100），但**主要是把侧栏塞进底部，不算真正适配**。重做方案：

| 端 | 宽度 | 布局 |
|---|---|---|
| **PC** | ≥ 1200px | 左侧固定导航（200px）+ 内容区（最大 880px 居中）+ 右侧信息栏（趋势/倒计时） |
| **笔记本/平板横屏** | 768–1199px | 左侧收窄图标栏（72px）+ 单栏内容 |
| **平板竖屏** | 640–767px | 顶部导航 + 单栏内容，卡片两列 |
| **手机** | < 640px | 底部 tab 栏（6 个）+ 单栏，卡片单列，按钮加大到 44px 触摸热区 |

**关键改动**：
1. 答题层要**真正全屏适配**（现在手机上是浮层，题干长了会挤）
2. 图表（趋势/模块掌握度）要能在手机上横向滚动
3. 题库图片（资料分析图表）要支持**双指缩放**
4. 打印样式单独保留（她要打印卷子）

## 十、风险与提醒

1. **密码是单点**。泄露 = 学习数据全暴露。管理密码尤其要强。
2. **加后端 = 多一个要维护的东西**。服务挂了她就刷不了题——所以设计上**前端本地照常能用**，同步失败只是后台看不到，不影响她学习。
3. **AI 代理意味着所有请求过主人的服务器**。这是必要的（保护 Key），但要记得服务器流量会上升。
4. **风格返工成本高**。所以阶段 1 先出样板。
5. **数据迁移**：她现在的学习数据在浏览器 localStorage 里，上线后要能平滑同步上去，不能丢。
