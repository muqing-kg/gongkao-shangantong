## 1. 背景

上一轮（2.18）移除了全部模拟题（44,312 题），但题库里还剩 882 道**原创题与开源练习题**
（`questions.js` ~ `questions4.js`）。用户要求：**只保留真题，其余一律不要**。

## 2. 为什么不能直接删文件

先查清结构，避免删错：

| 文件 | 作用 |
|---|---|
| `questions.js` | 声明 `政治理论`、`常识判断`、`言语理解` 三个模块 |
| `questions2.js` | 声明 `数量关系`、`判断推理` |
| `questions3.js` | 声明 `资料分析` |
| `questions4.js` | 把开源题 concat 到四个模块上 |

**`MODS` 来自 `Object.keys(QUESTION_BANK)`**，而 `normalizeStore()` 会用 `MODS` 过滤作答记录。
直接删掉 2/3/4 会让三个模块键消失，**她这三个模块的历史作答记录会在加载时被静默丢掉**。

因此做法是：

1. 把 `questions.js` 改写成一个**只声明六个空模块**的结构文件（0.5 KB）；
2. 删除 `questions2.js`、`questions3.js`、`questions4.js`；
3. `index.html` 只保留 `questions.js` 一个数据脚本。

首屏因此变成 0 题，12,908 道真题全部由 `lazy-bank.js` 异步加载。

## 6. 一个因题库变小而暴露的测试竞态

`app.js` 在题库加载完成时会做：

```js
if(currentView()==='dashboard' && ...) renderDash();
```

**这会覆盖 `#view`。** 而部分测试是直接调 `renderAnalysis()` 等渲染函数、不切标签页的，
此时 `currentView()` 仍是 `dashboard`——题库一加载完，测试刚渲染的页面就被冲掉了。

以前题库 164 MB 要 1–2 秒，冲不掉；现在只剩 29 MB，**0.3 秒就加载完，正好撞上**。
表现是 `test_v28_pace.py` 在套件里偶发失败（数据断言全过、渲染断言全挂），单独跑却通过。

修法：给「直接渲染视图」的 5 个测试在 `page.goto` 之后统一加一句等待题库就绪。

```python
page.wait_for_function(
    "() => window.LAZY_BANK_STATUS && window.LAZY_BANK_STATUS.loaded", timeout=120000)
```
