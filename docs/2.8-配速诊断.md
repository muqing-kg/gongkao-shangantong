# 上岸通 2.8 · 配速诊断

> 日期：2026-10-02 · 范围：把已记录的每题用时变成「时间花在哪、该放弃什么」的可执行结论

## 1. 要解决的问题

用户反馈：「行测做不完 / 正确率上不去」。

这不是内容不够的问题——题库已有 59,068 题，一天做 100 题要做 590 天。
行测 120 分钟上百题，**做不完的根因是取舍策略，不是不会**。

改造前的能力分析页只有两个全局平均值：

```
答对均时 59s    答错均时 89s
```

看不出**时间花在哪个模块**，也给不出任何取舍结论。而每题的用时其实早就记在
`store.attempts[].dur` 里了（`js/app.js` 的 `pick()` / `submitMulti()` 在切题时计算），
只是没被用起来。

## 2. 设计取舍：不引入外部「标准用时」

省考各省卷面差异很大（总时长、总题量、模块配比都不同），硬套一个「每题 60 秒」
的参考值会误导用户。因此本功能：

- **只用用户自己的数据**：以她自己各模块用时的**中位数**为界，划分四象限；
- **不给绝对目标**：不写「你应该 50 秒一题」，而是教她自己算
  「你报考省份的卷面总时长 ÷ 总题量 = 每题预算」，再跟实际用时对比；
- **样本不足不下结论**：带计时的作答少于 20 次，或只有 1 个模块时不渲染卡片，
  不输出假精确的结论。

## 3. 四象限判定

以「模块平均用时」和「模块正确率」相对她自己中位数的位置划分：

| 用时 | 正确率 | 定位 | 建议 |
|---|---|---|---|
| 快 | 高 | **优势区** | 考试先做，把分拿满 |
| 快 | 低 | **潜力区** | 补知识点收益最大 |
| 慢 | 高 | **稳但慢** | 需要专门练提速 |
| 慢 | 低 | **时间黑洞** | 考试放最后、限时、做不出直接蒙 |

卡片会点名最慢的「时间黑洞」和正确率最高的「优势区（基本盘）」，并统计
单题超过 90 秒的题数与占比。

## 4. 实现

改动集中在 `js/app.js`：

| 新增 | 作用 |
|---|---|
| `PACE_ZONE` | 四象限的名称、颜色与建议文案 |
| `paceMedian(arr)` | 中位数（偶数个取中间两数均值后取整） |
| `paceDiag()` | 汇总 `attempts`，返回各模块用时/正确率/象限与结论；样本不足返回 `null` |
| `paceCardHtml()` | 渲染配速诊断卡，数据不足返回空串 |

卡片插入 `renderAnalysis()`，位置在「模块掌握度」与「难度适配」之间。
未新增任何 CSS，沿用既有的 `.r-mod` / `.rm-bar` / `.rm-fill` 样式。

## 5. 验收

```
SAT_TEST_URL=http://127.0.0.1:8140/index.html python scripts/test_v28_pace.py
==== v2.8 配速诊断验收：通过 25/25，失败 无 ====
```

覆盖：

- 样本不足（1 次作答 / 只有 1 个模块）时 `paceDiag()` 返回 `null`、卡片不渲染；
- 构造 4 模块 × 8 题数据，验证中位数（用时 73、正确率 63）、平均用时（70 秒）、
  超时题统计（16 题 / 50%）逐项正确；
- 四象限判定：资料分析与数量关系为 `slowweak`，常识判断与言语理解为 `faststrong`；
- 时间黑洞取最慢者、基本盘取正确率最高者；
- 页面文案包含取舍建议与「总时长 ÷ 总题量」的预算算法；
- 卡片内不出现任何硬编码的外部参考用时。

## 6. 本次未做

1. **单题限时与超时提醒**。目前只有整卷倒计时（`Q.limit`），做题过程中看不到
   单题耗时。练「到点就走」需要这个。
2. **错因标注**。交卷后仍只能看到对错，无法标记「不会 / 来不及 / 粗心」。
   这三种错因对策完全不同，是提分最关键的一环，但需要新增数据字段与结果页交互。
3. **按考点的配速细分**。目前只按模块，`attempts[].point` 里已有考点字段可用。
